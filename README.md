 2026 # UG Call Centre — Внутрішній портал

Автономний портал із серверною авторизацією через Cloudflare Pages Functions. Не змінює поштовий інструмент або попередній портал. Інструкція з секретів, D1 та безпечного розгортання — у [AUTH-SETUP.md](AUTH-SETUP.md). Версію не опубліковано.

## Запуск

Для захищеної версії потрібен сервер Functions: виконайте `node build.cjs`, налаштуйте локальні секрети й D1 та запустіть `npx wrangler pages dev dist` за інструкцією AUTH-SETUP.md. Відкриття HTML напряму або через звичайний статичний сервер придатне лише для перегляду макета й не забезпечує авторизації.

## Структура

- `index.html` — шапка, вступ, компонент оператора, три принципи, ресурси, мета.
- `css/styles.css` — власний дизайн та адаптивна сітка 3/2/1.
- `js/portal-links.js` — назви, описи, іконки, акценти та URL дев'яти ресурсів.
- `js/app.js` — картки, модальні списки документів, пошук, перевірка URL та стани кнопок.
- `assets/ug.svg` — копія оригінального знака UG із поточного проєкту.
- `.nojekyll` — підтримка статичної публікації на GitHub Pages.

## Документи

Усі дані зберігаються в js/portal-links.js, у window.portalCatalog:

- categories — дев'ять карток. Поле category є ключем для прив'язки документів.
- resources — список документів; зараз порожній, бо справжніх документів не надано.

Щоб додати документ, вставте об'єкт у resources:

```js
{
  id: 'crm-guide',
  title: 'Регламент роботи на CRM',
  description: 'Правила роботи оператора в CRM',
  category: 'instructions',
  url: '',
  type: 'docs',
  status: 'pending'
}
```

Це приклад структури, а не доданий документ. Заповніть url справжньою абсолютною HTTP(S) адресою і змініть status на available, коли документ готовий. HTML редагувати не потрібно.

Типи: sheets (Google Sheets), docs (Google Docs), pdf, site (інший сайт).
Статуси: pending (очікує посилання), available (доступний), unconfigured (не налаштовано), unavailable (тимчасово недоступний). Коректний HTTP(S) URL позначає документ доступним, якщо він не має блокувального статусу unconfigured чи unavailable. Порожні, некоректні та небезпечні URL ніколи не відкриваються, навіть зі статусом available. Це перевірка формату URL, а не дозволів доступу до приватного документа. Зовнішні посилання відкриваються у новій вкладці з noopener noreferrer.

Для зарплати, ставок, KPI та прикладів використовуйте category: 'payroll'; для CRM, замовлень, ТТН, статусів, допродажів і передзвонів — 'instructions'. Інші ключі дивіться у categories. Додавайте лише свої справжні документи; назви з технічного завдання автоматично не створюються.

## Картки та пошук

Клік у будь-якому місці картки або її кнопка відкриває модальний список. Порожні категорії залишаються доступними з поясненням. Закриття — кнопка ×, Escape або натискання на фон поза вікном. Нативний dialog утримує фокус і повертає його до кнопки після закриття.

Пошук фільтрує документи за назвою, описом та категорією без перезавантаження. Не враховує регістр, нормалізує апострофи; усі слова запиту мають зустрітися в тексті. Картки категорій залишаються на місці. У результатах є тип документа, опис, статус та кнопка. За відсутності URL показується «Посилання ще не додано», а кнопка неактивна.

## Перевірки

У Chrome перевірено 1440, 1280, 768, 430, 390, 375 та 360 px: сітка 3/2/1, без горизонтального прокручування та обрізаних карток/кнопок. Перевірено відкриття категорій, порожній стан, пошук і очищення, типи/статуси, дозволені й небезпечні URL, закриття модального вікна трьома способами та мобільну панель. Помилок JavaScript у консолі не виявлено.

Для повторення: node check-browser.cjs "C:/Program Files/Google/Chrome/Application/chrome.exe". Тестові ресурси додаються лише в пам'ять браузера й не записуються у конфігурацію. Скрипт створює тимчасовий профіль .qa-browser; не включайте його до публікації.

## Ілюстрація

Оригінальної ілюстрації оператора та прикріпленого референсу серед доступних файлів немає. У `.operator-visual` підготовлено окремий декоративний SVG-компонент оператора. Його можна замінити на `<img src="assets/operator.webp" alt="">`, не змінюючи структуру сторінки. Знак UG збережено з наявного `favicon.svg`; повного окремого логотипа не знайдено.

## Розгортання

Дотримуйтеся [AUTH-SETUP.md](AUTH-SETUP.md). Публікувати потрібно лише `dist` із Pages Functions через Git-інтеграцію або Wrangler. GitHub Pages та звичайне статичне завантаження не виконують серверну авторизацію.

## Етап 3: щоденна навігація

Швидкий доступ налаштовується через quickAccess у js/portal-links.js. category відкриває категорію; optional resourceId відкриває конкретний налаштований документ. За відсутності коректного URL відкривається категорія.

Кожен документ має унікальний постійний id. Зірочка біля назви додає або прибирає документ з обраного; фільтр «★ Обрані» показує вибране. Обране зберігається під ключем ug.portal.favorites.v1, історія — ug.portal.recent.v1 у localStorage конкретного браузера. Між користувачами або пристроями дані не синхронізуються. При недоступному localStorage робота продовжується у пам'яті сторінки з повідомленням.

Історія містить максимум п'ять унікальних документів; повторне відкриття переміщує документ нагору. Реєструється лише відкриття дозволеного URL, включно із середньою кнопкою миші. Порожні або заблоковані ресурси не записуються. Є очищення історії. В історії зберігаються лише id, а не копії URL.

Поле priority у документі задає порядок: більше число — вище; за однакового значення зберігається порядок конфігурації. За відсутності поля використовується 0. Наприклад, додайте priority: 100 до важливого документа.

Фільтри працюють разом із пошуком і не перейменовують дев'ять карток. «Графіки» об'єднує schedule і extra-shifts; «Розрахунки» — payroll, extra-shifts і fines; «Інструкції» — instructions, roles і faq; «Навчання» — training. «Регламенти» — regulations. Порожні категорії доступні у відповідному фільтрі та через «Усі ресурси». На телефоні панель фільтрів прокручується горизонтально всередині власного контейнера.

Перевірено у Chrome: обране (додавання/видалення/перезавантаження), історію (ліміт 5, без дублікатів, повторне відкриття, перезавантаження, очищення), пошук разом із категоріями й обраним, priority, незадані та небезпечні URL. Перевірені ширини 1440/1280/768/430/390/375/360 та заповнене мобільне модальне вікно. Помилок JavaScript не виявлено. Тестові документи існували лише в пам'яті QA-браузера; resources у конфігурації залишається порожнім.

## Єдина система модальних вікон

Усі вісім головних карток відкривають один спільний dialog із тематичною іконкою та акцентом. У конфігурації js/portal-links.js:

- categories — головні картки; modalDescription — опис діалогу.
- categories[].sections — підкатегорії: id, title, description, category, icon, accent, type, status, resourceIds.
- resources — справжні документи з URL; їхні id залишаються сталими для обраного й історії.

Щоб підключити документ, додайте запис у resources і його id у resourceIds відповідної підкатегорії. Один id можна використати кілька разів: для двох пунктів додаткових виходів і штрафів використовується лише один запис extra-shifts-and-fines. Кілька resourceIds відкривають вкладений список документів. Порожні підкатегорії є позначеними місцями майбутнього підключення, а не вигаданими документами.

Для FAQ у відповідній підкатегорії додайте questions: [{ question: 'Ваше питання', answer: 'Затверджена відповідь' }]. Зараз усі масиви питань порожні. Відповіді виводяться без HTML через textContent.

Пошук знаходить назви головних розділів, підкатегорій, документів і внесених FAQ. «Переглянути» відкриває потрібний розділ із підсвічуванням знайденого пункту; тільки «Відкрити» всередині діалогу переходить до документа й записує його в історію. Обране залишається прив'язаним до документа, а не до його відображення в підкатегорії.

Підключені 7 унікальних документів: 5 регламентів, графік операторів та спільна таблиця додаткових виходів/штрафів. Решта пунктів очікує підключення. Для регламентів залишено композицію 3+2; інші вікна використовують узгоджену адаптивну сітку.
