# Команда онлайн

## Підготовка бази перед публікацією

Нових секретів або binding не потрібно. Використовується чинний `AUTH_RATE_LIMIT`, підключений до D1 `ug-portal-auth`.

Виконайте SQL із `migrations/0002_session_presence.sql` у консолі **наявної** D1-бази Cloudflare або через Wrangler з налаштованим ідентифікатором цієї бази:

```sh
npx wrangler d1 execute ug-portal-auth --remote --file=migrations/0002_session_presence.sql
```

Команда змінює production-базу — її виконує власник перед ручним розгортанням. У межах цієї роботи вона не виконувалася. Міграція лише додає таблицю й індекс; наявні сесії та ліміти входу не видаляються. Повторне застосування безпечне. Міграція `0001_auth_rate_limit.sql` має бути вже застосована.

Завантажте змінені серверні та клієнтські файли разом зі збереженням шляхів від кореня репозиторію. Звичайна команда збірки лишається `node build.cjs`, директорія статичних файлів — `dist`. `functions` і `server` залишаються в корені проєкту. Не змінюйте `PORTAL_PASSWORD`, `SESSION_SECRET` чи binding.

## Поведінка

- Ім’я вводиться разом зі спільним паролем. Сервер нормалізує пробіли та Unicode, приймає від 1 до 80 символів, відхиляє керівні символи. Ім’я не підтверджує особу й не створює профілю.
- Окремий запис пов’язаний із серверною сесією. Кілька вкладок одного браузера мають один запис; різні браузери/сесії можуть показувати однакове ім’я окремо.
- Видима сторінка надсилає POST `/api/presence/heartbeat` та GET `/api/presence` приблизно раз на 30 секунд. Онлайн — лише чинна сесія з активністю за останні 90 секунд. Після приховування вкладки оновлення призупиняються; при поверненні відновлюються.
- Імена повертаються лише авторизованим користувачам. Ідентифікатори сесій API не повертає. Клієнт не може змінювати ім’я або чужу присутність через heartbeat.
- Вихід видаляє запис. Прострочені сесії відразу виключаються із запиту списку; фізичне очищення прострочених сесій і залежних записів відбувається під час наступного створення сесії.
- Старі сесії продовжують працювати, але без імені. Для появи в списку користувачу потрібно вийти та увійти знову; про це є підказка в блоці.
- За помилки таблиці присутності вхід працює, блок показує помилку й автоматично повторює запит. Загальна недоступність D1 може блокувати чинну серверну авторизацію: обхід захисту не додавався.

## Локальні перевірки

```sh
node check-release.cjs
node check-presence.mjs
node check-auth.mjs "C:\Program Files\Google\Chrome\Application\chrome.exe"
node check-browser.cjs "C:\Program Files\Google\Chrome\Application\chrome.exe"
node check-cloudflare.mjs
```

Остання перевірка використовує локальний Wrangler/workerd і локальну D1. Вона не розгортає сайт. Перед ручною публікацією переконайтеся, що міграцію застосовано саме до бази, прив’язаної до Production; після публікації перевірте два різні браузери, вихід і зникнення неактивної сесії через 90 секунд.
